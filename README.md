# CameraFrameworkEditor · 相机框架编辑器 v0.6.0

## UE 实时参数调试

编辑器打开 Lua 工作区后自动建立调试会话，状态栏显示“UE 调试就绪 · Ctrl+S”。首次更新配套 Lua 代码和 Test 输入映射后，重启一次 UE PIE；之后保持 UE 游戏视口焦点，按左 Ctrl+S，编辑器会在后台提交所有编辑窗口的待提交参数、保存全部草稿、校验真实 Lua 资产并更新后处理计划。只有保存成功，LuaPlayer 才在 Tick 末尾重装相机；状态栏会显示保存、等待重装和 UE 已更新的结果。失败原因可在状态提示及 Lua 日志查看。

Ctrl+S 使用 UE 既有 InputSystem 的 Test.ResetCameraRuntime 映射，经过工作区 .editor/live-debug/ 的请求与回执通知后台编辑器。没有系统全局键盘钩子或按键注入，不影响其他应用的保存快捷键，也不切换焦点。会话和请求按工作区隔离，重复输入合并，过期会话及旧请求不能触发重装。编辑器离线时，UE 的左 Ctrl+S 仅重新读取已经保存的磁盘参数。

相机重装会清理资产缓存，保留当前装置请求、镜头画面和后处理历史；候选装配失败继续使用旧相机。外部镜头接管期间延后重装。此功能更新资产参数，Lua 模块源码变更仍需项目原有热更新或重启。正常的编辑器内 Ctrl+S 保留“保存当前文件”的行为，UE 中的调试 Ctrl+S 保存全部草稿。

新增回归入口：`node --test tests/live-debug.test.cjs` 验证真实 Lua 客户端握手、保存与失败隔离；`node tests/live-debug-ui.cjs` 验证多草稿后台保存、重装确认和焦点保持，支持 `--packaged`。

独立 Windows 桌面应用。工具与项目分开存放；编辑器直接扫描框架内的资产文件，引用使用相对于 `CameraFramework/` 的明确路径。不再需要 `Index.json` 或资产稳定 ID；目录仅用于物理组织。

## 启动

仓库地址：`https://github.com/HanLi788/CameraFrameworkEditor.git`。本地目录可自行命名，构建和运行使用项目相对路径。

从仓库首次拉取后，安装 Node.js 22.12+（含 npm），在项目根目录执行：

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
```

已有打包产物时，可运行 `release/win-unpacked/相机框架编辑器.exe`，或使用本机的 **相机框架编辑器.lnk**。快捷方式不纳入 Git；移动或重命名目录后，需要更新其目标路径和起始位置。`node_modules`、`dist`、`release` 同样不纳入 Git，首次拉取后需安装依赖并构建。

启动后选择 **Lua 工作区目录**（例如 `D:\MyWorks\Lua`）。工作区包含 `CameraFramework`、`InputSystem`、`Foundation` 三个核心目录；试玩另需 `Actor/Player/PlayerEvents.lua` 和 `MovementValues.lua`。打开时检查依赖，缺失会明确报出路径。旧的 CameraFramework 最近记录兼容归一为父级 Lua 目录；存档仍沿用原框架路径标识。编辑器使用仓库内 `runtime/` 提供的 Lua，无需另行安装 Lua 或 UE 编辑器。

发布目录 `release/win-unpacked` 可整体复制运行，无需另装 Node.js 或 Lua；不要单独复制 exe。

## 构建编辑器

双击工具根目录的 **构建编辑器.bat**。批处理调用随仓库提供的 `scripts/build-editor.ps1`，检查 Node.js 22.12+ 和 npm，缺少构建依赖时按 package-lock.json 自动安装，再显式准备 Electron 运行文件，随后编译并生成可直接运行的编辑器目录（release/win-unpacked/）和 Windows x64 NSIS 安装包。首次下载依赖、Electron 或 NSIS 工具需要联网；成功提示同时显示程序与安装包路径。

失败时保留原始工具输出，并用中文说明失败步骤、原因和建议；下载超时、证书校验、文件占用、磁盘不足、文件完整性和编译错误分别处理。Electron 下载超时时提示当前 PowerShell 会话的镜像设置方法，不自动切换下载源。详细日志写入 `logs/build-editor.log`，每次构建覆盖；日志不会随临时文件清理。

每次构建为工具的 TEMP/TMP 分配独立临时目录。按 Enter 退出时立即清理；直接关闭构建窗口时，由隐藏清理进程等待构建进程结束并重试清理。仅删除具有本次会话标记的专属目录，不遍历目录链接，不清理全局 TEMP。保留 node_modules、Electron/npm/打包工具的可复用下载缓存、dist 与 release；失败后原有发布文件可能仍在，因此以本次“构建成功”提示判断结果。同一项目目录同时只允许一个构建进程。

输出为 `release/CameraFrameworkEditor-<版本>-Setup.exe`，安装向导支持选择安装目录、创建桌面快捷方式。安装程序包含应用和 Lua 运行时，使用者无需安装 Node.js；Lua 工作区仍由启动后自行选择。

自动化调用可用 `构建编辑器.bat --no-pause`，成功返回 0，失败返回非 0。`npm run package` 保留免安装目录构建；`npm run package:installer` 仅打包当前 dist，需先执行 `npm run build`。

当前 Electron 将二进制下载延迟到首次运行；仅执行 `npm ci` 可能尚未生成 `node_modules/electron/dist`。批处理及两个 npm 打包命令均先执行 `npm run electron:install`，通过已安装 Electron 包的安装器下载并校验对应版本，已有匹配运行文件时直接复用。缺少运行文件不再触发重复安装全部依赖。若下载失败，可检查网络后重试该命令；不要手工创建空的 dist 目录。机制见 [Electron 安装说明](https://www.electronjs.org/docs/latest/tutorial/installation)。

GitHub 下载较慢时，可在单次 PowerShell 会话中设置 Electron 文档列出的镜像后运行脚本，安装器仍使用包内校验和验证下载文件：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
.\构建编辑器.bat --no-pause
```

## 工作区

- 主窗口采用“目录 + 装置空间”布局，装置资产树占满右侧；节点详情在固定宽高为视口 75% 的居中弹窗中编辑，不再常驻占用树区。场景仍在独立游戏窗口中；主编辑区围绕装置及其依赖展开。
- 左侧目录从 Assets 开始，显示文件夹、资产和普通文本文件。单击文件夹展开或收起；单击 `.rig` 切换装置工作区，恢复本次会话中上次选中的节点、展开状态和缩放，不自动打开详情。普通资产、Lua 和 Markdown 使用同一个详情弹窗独立编辑，保留背后的装置树，不自动选择引用装置。
- 装置树以 `.rig` 为根，按管线、范围、输入、灵敏度、遮挡、效果、平滑等实际引用分组，继续向下展开值资产和曲线。只展示资产关系，参数在详情弹窗中编辑。树区支持 Ctrl + 滚轮以鼠标位置为中心缩放，按住右键拖动画布；可独立滚动、适应宽度及展开／收起各分支。缩放和拖动偏移随本次会话的装置空间恢复。
- 单击节点打开详情弹窗并高亮节点及其祖先路径；根节点编辑装置本身。弹窗显示彩色资产图标、完整文件名、相对路径、共享提示及源码／资产切换。从详情打开引用资产在同一个弹窗中切换，可逐级返回，也可用“同级资产”选择器快速切换。所有位置共用按文件路径管理的一份草稿、撤销和保存状态。修改引用后，树和共享统计随草稿更新；无效 JSON 草稿保留已保存结构并给出提示。
- 共享节点显示链环图标和引用它的**不同装置数量**，同时统计直接和间接引用。同一装置中的多次引用只计一次。悬停可看影响装置列表，点击打开影响范围窗口，再选择装置可跳到该装置下的同一资产。独立编辑共享资产也显示此提示。
- 缺失引用与循环引用显示警告并终止相应分支展开；异常过深或过大的依赖图会截断显示。共享资产是正常关系，不使用警告图标。
- 目录顶部搜索文件路径；右键文件夹选择新建资产类型（Rig、Input、Value、Curve 等），填写名称主体，由系统添加固定后缀并使用模板创建合法结构。Input 可通过模板选择输入类型，Curve 提供两个父类型模板。右键也可新建文件夹。
- F2 重命名时后缀显示为只读，只修改名称主体；Ctrl+C / Ctrl+V 复制，Delete 删除，拖拽文件／文件夹到目录执行移动。详情挂载通过资产选择器更换，挂载数组仍可在弹窗内拖拽排序。移动与重命名更新资产引用；被外部资产引用的文件或文件夹不能直接删除。Lua 业务代码中的字符串路径仍需自行同步。
- 主进程集中管理草稿、撤销、重做及保存状态。多个窗口修改不同字段可以合并，过期的同字段写入会被拒绝。
- X、Esc 或 Ctrl+W 关闭详情时保留草稿，不保存也不丢弃；点击遮罩不关闭。Ctrl+S 保存当前资产，“还原草稿”显式丢弃修改。保存只处理当前节点／独立文件，全部保存处理所有草稿（包含当前不可见的草稿）。退出应用和切换项目会检查全部草稿；关闭游戏窗口不会丢弃资产草稿。
- Markdown 默认预览，提供源码／预览切换；预览读取当前草稿，支持标题、列表、表格、代码块和框架内 PNG/JPEG/GIF/WebP 图像，不执行内嵌 HTML。相对文件链接在编辑器打开，HTTP(S) 链接点击后交给系统浏览器；远程图像显示替代文字。正常中文和中文标点不再显示黄色 Unicode 边框，仍保留不可见控制字符提示。
- 普通详情表单不显示 SchemaVersion；协议字段仍保存在文件中，并参与加载及校验，可在源码模式查看。
- 弹窗随主窗口尺寸保持 75% 宽高，表单占满弹窗可用宽度，内容独立滚动；字段保持自然高度。

## 可玩的相机试验场

游戏设置的帧率上限支持 30、60、90、120 FPS，同时控制 Lua 逻辑和画面的目标频率。每个逻辑步按所选频率传入 1/FPS 秒，依次更新输入、角色、碰撞、相机及后处理；画面直接显示最新结果，没有额外的显示插值缓冲。暂停时可以修改频率，保存后保持当前时间、姿态和装置，继续游戏即使用新步长。设置会持久化，菜单背景仍为 30 FPS，实际画面帧率受显示器刷新率和渲染性能限制。

调度器按单调时钟累计待执行步数，每批最多补执行 8 步并让出事件循环，不丢弃落后时间、不扩大 DeltaTime。暂停和恢复重新建立墙钟基准，不补算暂停时间。视口右下角分别显示画面 FPS、最近实际逻辑频率／目标 Hz，以及存在时的落后毫秒数；性能不足时会显示落后，不能保证任意设备都持续达到目标频率。

帧率回归：`node --test tests/simulation-clock.test.cjs tests/frame-rates.test.cjs tests/render-frames.test.cjs tests/game-worlds.test.cjs` 检查分批追帧、30/60/90/120Hz 实际 Lua 步长、移动距离、过渡时长、平滑响应及设置持久化；`node tests/frame-rates-ui.cjs` 检查实际窗口中的频率同步、暂停切换、最新姿态和诊断显示，支持 `--packaged`。

独立游戏窗口使用程序化像素方块原野，玩家与 NPC 均为编辑器原创方块人物：青色上衣玩家、赭黄色上衣向导，保留行走、奔跑、跳跃与对话表现。地图和人物无需外部模型或纹理；不提供地图搭建、Actor 放置或层级编辑。

主窗口绿色 **▶** 只打开游戏主菜单，不启动 Lua 模拟；重复点击聚焦已有游戏窗口。红色 **■** 结束游戏并关闭窗口，效果与游戏窗口的原生关闭按钮相同。窗口大小和位置会记住。

游戏主菜单背景为缓慢环绕的实时场景动画，不发布能力事件。中央纵向排列“开始游戏、新建世界、选择存档、游戏设置”，显示当前选中的世界；菜单本身没有种子输入框。

- **默认实验场**：存档列表中始终提供的内置入口，每次从固定出生点开始；包含 NPC 广场、台阶、坡道、遮挡墙和狭窄通道，并有草地、湖水、沼泽与木栈道。
- **新建世界**：进入创建页面，填写 1–64 个字符的世界名称与种子，种子右侧按钮随机填入新值。“创建并进入”保存世界信息，然后加载探索世界。相同种子、生成器版本和参数得到相同地图，当前版本为 v1。
- **探索世界不生成对话 NPC**：无 NPC 模型、NPC 身体碰撞、气泡或 Dialogue 激活入口；其他基础动作能力照常运行。
- **选择存档**：选择默认实验场或已创建的探索世界，返回菜单后点击“开始游戏”。已有世界的种子只读，避免改变已保存的世界。
- 当前地图为 128 × 128 米、4 米地块的有限场地。种子改变地形起伏、水域范围、树木和石块；出生点、NPC 与主要通路保留安全区域。

地图与碰撞共用同一份几何描述，在后台工作线程生成，合并重复请求并缓存最近两张地图；渲染按材质实例化。草地、泥土、石头、木纹、树叶与水面采用程序化像素纹理，近处以最近邻采样保留清晰像素。地表按米重复纹理，不将一张小图拉伸覆盖整面墙。此次风格更新保持 v1 地图几何、种子和碰撞不变；人物仍高 1.76 米，沿用既有 NPC 引用、Id 与对话构图。正常运行不加载第三方城镇或角色，安装包也排除旧地图、旧角色模型和旧碰撞缓存；源码保留它们用于历史回归。

点击主菜单的 **开始游戏**（或 **创建并进入**）后进入至少 1 秒的加载界面。地图、材质与 Lua 配置就绪后才推进游戏；准备超过 1 秒则按实际耗时等待。加载可取消并返回菜单，失败显示原因并可重试。进入后点击场景取得键盘焦点：

| 操作 | 能力 / 对应真实装置 |
| --- | --- |
| WASD | 移动，Jog |
| Q + WASD | 奔跑，Run（试玩给 AbilitySlot06 分配的能力） |
| C + WASD | 慢行，Walk（试玩给 AbilitySlot09 分配的能力） |
| Space | 起跳与落地，Jump；空中不能重复起跳 |
| Shift | 短冲刺，Dash；有冷却，不能在对话中使用 |
| 左键拖动 / 滚轮 | 经当前装置的输入资产改变观察角度 / 距离 |
| 点击 NPC 气泡 | 进入 Dialogue |
| 对话面板右上角 × / Esc | 结束对话并执行退出过渡 |
| 非对话时 Esc | 暂停／继续游戏 |

以上按键是当前工作区的默认配置，实际绑定来自 `InputSystem/MyIMC/Definition/Definitions/*.json`。试玩运行真实 `InputSystem.InputManager`，链路为：浏览器物理按键／鼠标信号 → RuntimeHandle.OnPressed/OnReleased/OnChanged → SignalManager → KeyManager → IMCManager → InputHandle → 角色能力与相机 InputService。每个逻辑帧使用所选帧率对应的固定步长，先更新输入，再更新角色和相机；宿主只适配文件读取、目录扫描、时钟及原始设备信号。相机挂载的 IMC 由框架自身激活／停用，不再使用伪造 HasMapping 或直接赋值 LookTurn 的句柄。

角色读取 Character/MoveForward、MoveRight 的真实值，保留小于 1 的轴幅度；Jump、Dash 订阅 SourceStarted，短按与组合键生命周期由真实输入系统处理。Run、Walk 优先读取同名映射，未定义时分别使用 AbilitySlot06、AbilitySlot09。鼠标向上转换为正 MouseY，滚轮转换为正向上滚的原始单位，观察灵敏度属于设备侧增益；映射响应、平滑、倍率和资产权重仍由 Lua 处理。Esc 暂停／退出和 NPC 气泡属于编辑器窗口／交互界面命令。失焦发送真实释放信号，暂停在原时间清理按键；映射自身的平滑尾部仍会按配置收敛。

每次开始游戏重新读取 InputSystem 源码和 JSON 定义；在外部修改绑定后返回菜单重开即可应用。未知必需映射、缺失模块、非法定义会阻止启动。资产树仍专注 `CameraFramework/Assets`，引用保持 `Assets/...`，选择 Lua 根目录不会改写资产路径。

能力状态发布同级 `Actor/Player/PlayerEvents.lua` 中的真实事件；注册 Walk、Jog、Run、Jump、Dash、Dialogue，由当前项目的 `CameraSpaceManager`、装置及管线计算镜头。不会自动激活编辑器中选中的装置，也不会在两秒后自动退出。自动生命周期演示仅保留在回归测试接口中。

主窗口资产树与详情表示**正在编辑的装置和资产**；游戏视口左下方显示**生效装置、过渡阶段和能力**。切换装置工作区或浏览其他资产不打断游戏。十二通道面板展示真实目标、渲染与最终输出。运行读取全部当前草稿的独立快照，修改后返回主菜单再开始游戏应用；运行本身不保存资产。

NPC 仅在默认实验场中生成，位于固定位置。角色距离 NPC 360 cm 内且无遮挡时可交谈；气泡跟随 NPC 屏幕位置，镜头外或墙后隐藏。点击后发布 `{Id=9999, Target=npc}`，进入对话面板并锁定移动和观察输入，重复点击不会重复激活。若动作装置尚未退出，先等待框架释放动作空间。关闭对话发布 `DialogueEnded`，退出完成后恢复角色控制。暂停时也可关闭面板，镜头退出过渡在继续游戏后推进。

项目需挂载 `Assets/CameraAssets/InteractiveCamera/Player/Dialogue/ValueAssets/Dialogue_9999.value`：在 `Dialogue_Enter.input` 的 `ValueAssets` 中加入对应 `Id: 9999` 和 `Path`。Id 选择构图配置，Target 提供实际位置、旋转和胶囊引用，不能只添加文件而不挂载。内置 NPC 高约 176 cm，9999 资产提供对应的十二通道构图；原来的 10001、10002 示例保留。

暂停冻结 Lua、角色动画和水纹。窗口失焦、点击编辑控件会释放角色输入，窗口隐藏时自动暂停。“返回主菜单”结束本次模拟并保存探索进度；默认实验场再次进入时从固定位置开始。

探索存档保存世界名称、种子、生成器版本、最近落地位置与朝向，每 5 秒自动保存，返回菜单与关闭游戏窗口时也保存。空中退出恢复最近一次安全落地位置。存档不会保存相机参数或装置状态，重新运行读取编辑器的当前配置。存档按项目绝对路径隔离，位于 `%APPDATA%/CameraFrameworkEditor/game-worlds/<项目路径哈希>.json`；移动项目目录后会视为不同项目。

游戏设置目前提供实际生效的画质（阴影与像素比）、30／60 FPS 帧率上限、观察灵敏度和 0.25–4× 移动速度倍率；与世界选择一同持久化。运行中点击“游戏设置”会暂停游戏，可调整后保存，再继续。倍率作用于慢行、普通移动和奔跑，真实位移速度反馈给 Lua；冲刺速度、跳跃参数、时间推进与相机过渡时长不变。游戏始终使用装置相机，不提供自由观察；主菜单保留自动环绕动画。当前无音频，因此不提供无效的音量滑块。

地图静态 BVH 同时用于相机球体扫掠和简化角色运动。角色具有重力、落地、小台阶、墙体阻挡、NPC 身体阻挡和跌出地图后的复位；这些能力仅用于编辑器体验，不等价于 UE CharacterMovement。游戏界面默认启用相机与角色地图碰撞；历史回归接口仍可独立禁用相机碰撞。框架输出的遮挡透明度应用到对应网格；相机缩距仍受资产范围约束。游泳、滑翔、钩索等未实现能力，以及 UE 物理、复杂运动、后处理与真实游戏联调，仍在 UE 中验证。

水面使用轻量透明材质与程序化水纹，沼泽具有局部雾色变化；水域目前可浅水行走，尚未实现游泳或水下效果。这些环境供相机体验与后续渲染实验，不代表已实现 UE 后处理。

菜单背景最多 30 FPS，游戏按设置限制为 30／60 FPS；低、中、高画质的像素比上限分别为 1、1.5、2，低画质关闭阴影。视口显示实际帧率、绘制调用与三角形数。性能取决于硬件、窗口尺寸及视角。固定实验场含约 1,363 个方块和 1.53 万个碰撞三角形；实例化避免逐方块绘制。加载失败可重试，不在运行时联网下载。

当前模型与纹理由编辑器代码生成，未使用《我的世界》的原版纹理、皮肤或模型。历史下载素材的完整许可、来源与校验和仍保留在 [CREDITS](public/preview/CREDITS.md) 和 [sources.json](public/preview/sources.json)，用于源码回归记录。

恢复下载素材（包含历史城镇）：`node scripts/fetch-preview-assets.mjs`。旧城镇 BVH 回归数据：`node scripts/build-preview-collision.mjs`；程序化地图无需预生成碰撞文件。测试：`npm test`、`node tests/preview-ui.cjs`、`npm run test:ui`；界面测试添加 `--packaged` 可检查原 `release/win-unpacked` 中的程序。测试夹具需当前框架、同级 InputSystem（含 JSON 定义）、Foundation，以及 `Actor/Player/PlayerEvents.lua` 和 `MovementValues.lua`。

## 引用槽与图标

引用槽显示资产图标和完整文件名，支持选择、拖入、在当前详情弹窗打开、定位到目录及查看引用方。曲线另有直接选择已扫描到的曲线资产的下拉框。

定位操作会激活主窗口，展开目标目录、清除目录搜索、选中并滚动显示目标文件。详情分组每层缩进 12px，并使用细边线表达层级。

界面使用统一 SVG 图标；图标按钮提供悬停提示和无障碍名称。挂载使用紧凑行：左侧拖拽手柄、资产图标与名称，右侧依次为替换、打开、定位、查看引用和更多操作。完整路径及描述在名称悬停提示中查看，不常驻显示数组下标或资产类型；更多操作提供“移除挂载”。数组标题右侧的加号添加挂载，空数组可点击或从目录拖入资产。

按住手柄拖动时卡片跟随鼠标，其他项让出落点；靠近滚动区边缘时自动滚动，松开后提交一次可撤销的排序，Esc 取消。也可聚焦手柄后使用上下方向键调整。目标值候选槽使用相同排序交互，保留业务 ID 和首槽“默认”标记。

数组标签后的问号在悬停或聚焦时解释顺序含义：输入选取首个活跃来源，范围／灵敏度／平滑逐通道选取首个启用配置，效果按顺序求值并累加贡献，过渡按 Phase 区分用途，目标值按业务 ID 选择且首槽作为默认。管线当前恰好一个，遮挡最多一个，生命周期过渡最多 Enter、Exit 各一个；必需的最后一个挂载不能移除。效果不设权重，贡献由各输出的 Range 与 Curve 决定。用户输入每通道权重仍位于 `.input`，允许负数。

## 曲线工作流

引用处始终显示只读曲线预览，没有控制点拖动或参数编辑入口。替换引用只修改引用方，不修改曲线定义。

1. 在目录树选择希望存放曲线的位置，例如 `Assets/CameraAssets/ActionCamera/Player/Dash/CurveAssets/`。
2. 右键文件夹选择“新建资产 → Curve”，填写名称主体，后缀 `.curve` 自动添加。
3. 选择父类型 Bezier 或 CubicHermiteSpline，确认后创建资产，同时打开曲线详情弹窗。Gaussian 仍为预留类型。
4. 在曲线弹窗调整控制点或参数并保存。返回引用方，通过下拉框选择新曲线，再保存引用方。

Hermite 样条支持添加节点、删除选中内部节点、拖动节点与切线手柄，以及右侧精确数值输入；选中节点在图表和参数区同步。添加按钮在最大间隔中插入节点，保留原曲线形状和切线；双击图表可在指定位置添加。端点不能删除，X 保持 0/1，内部 X 严格有序。切线仍是单个 `Tangent = dy/dx`，支持负数输入，不创建左右独立切线。一次拖动形成一次可撤销编辑。

曲线图支持 Ctrl + 滚轮缩放、右键平移、适应曲线及重置视图。切线造成的 [0,1] 区间外极值会显示警告；保存继续使用真实 Lua 校验，包括过渡曲线的单调约束。引用槽的曲线图仍然只读。

新建曲线使用父类型模板，不依赖已有模板资产。资产创建于右键选择的文件夹，名称由用户指定；重名文件会被拒绝。装置文件直接放在场景目录，例如 `Assets/CameraAssets/ActionCamera/Player/Dash/Dash.rig`；创建或复制装置时会预留同级 `PipelineAssets/`。公共效果放在 `Assets/EffectAssets/`，宿主速度效果归入 `OwnerVelocity/`，不再预留每个装置的空效果目录。

曲线详情弹窗正常保存当前文件，不另存新资产、不自动改绑引用。窗口列出引用此曲线的资产，保存后所有对应预览刷新，引用方文件不被重写。需要独立变体时，先手动新建或复制曲线，再替换引用。切换父类型会重建控制点，可撤销。

## 目标值与过渡输入

过渡输入版本 4 使用 ValueAssets 候选槽数组 `{Path, Id?}`、内部 Phase 和统一 Duration，不再内嵌通道或 bTargetsById。目标值 .value 版本 2 保存完整十二通道及各自值、类型、参考、采样方式和曲线引用。

在 ValueAssets 文件夹右键新建 Value 资产，从模板复制完整通道；双击在主窗口的新标签中编辑。引用槽只允许挂载 Value 类型。数组支持增删、排序；第一槽显示“默认”。业务 ID 可不填写，也可选安全整数或非空字符串。数字 10001 与字符串 "10001" 不相等。

未传入交互 Id 时选择第一槽；传入未知 Id 则校验失败。退出过渡使用自身第一槽。目标槽数组不是镜头播放序列。业务 Id 仅用于目标槽选择，不是资产身份；槽中的 Path 明确引用目标文件。

保存会校验全部目标（包括未选中目标和关闭通道）；共享目标值保存后引用关系保持不变。编辑器按所选框架实时扫描资产，不依赖固定数量或固定目录名。

## 效果来源与输出

效果资产 Source 仅保存 `Object`、`Interface`、`Params`。上下文直接属性由 CameraContext 的对象槽位声明提供，接口名、参数结构、调用方式和返回类型由工作区 `CameraFramework/CameraSystem/Effects/InterfaceRegistry.lua` 声明。对象和接口使用原名下拉，参数按声明生成控件；资产不保存成员调用标记。

引用与来源结构在保存时通过实际 Lua 加载器校验。对象和方法在装置安装时检查，CurrentTarget 可延后至实际求值；运行时第一个返回值必须是有限数字或布尔值，false／true 按 0／1 处理。项目静态校验不会执行任意业务函数，也无法证明真实 UE 对象具有这些方法。

效果文件版本 9 共享一个 Domain，每个 Outputs 项仅包含 Range 和 Curve。Domain 支持 `[0,300] or [600,999) or {500}` 等有界区间／点集／并集；域外本资产当帧不贡献，所有片段共享全局上下界归一化。表单即时提示集合语法与单点约束，最终保存仍由工作区 Lua 校验器裁定。

Range 表示增量贡献，当前支持有限闭区间或单点。单点 Domain 必须对应单点 Range；常量输出可以在表单移除曲线，也能重新添加。非单点 Range 必须指定曲线。新增输出使用 `[0,1]` 与 Linear；单点 Domain 或无可用曲线时创建 `{0}` 常量。支持 `AnchorLocOffset.X` 等带点参数名。效果根、挂载与输出均不再接受 Weight、死区、中性值或溢出策略；旧版不会自动迁移。

曲线在引用处保持只读，可打开原曲线详情编辑。Hermite 允许下降、平台与非单调映射，过渡／平滑引用仍遵循其单调进度契约；保存共享曲线时校验所有使用方。

预览使用自身的 Owner、CurrentTarget 等模拟对象。若项目旁存在 `Actor/Player/MovementValues.lua`，宿主加载其中的函数供预览角色使用，因此现有速度效果沿用项目业务实现。其他业务对象或方法需要在预览适配中提供；缺失时明确报错，不替换为零，也不连接或关闭 UE 编辑器进程。实际 UE 业务接口仍需在引擎中验证。

## 保存、校验与恢复

- 表单与 Monaco 源码编辑共享文档状态；支持 Lua、JSON、Markdown 等 UTF-8 文本。
- 保存前调用所选框架的真实 Lua 加载器，校验曲线及其使用方。全部保存会联合校验相关草稿；F7 可校验项目及文本草稿。
- 外部文件变化时，干净文档自动刷新，有草稿的文档显示冲突，保存不会直接覆盖外部版本。重新载入可通过撤销恢复先前草稿。
- 新文件自动被扫描识别，无需登记。移动资产会同步更新框架内资产文件的引用并联合校验，被引用资产不能删除。创建或复制可与其他文档草稿并存；移动、删除前需处理草稿。业务 Lua 脚本和框架外的路径不自动重写，移动装置或脚本直接加载的资产后需要同步调用处。
- 文件操作不进入编辑撤销栈，写入前创建恢复副本，可捕获的多文件写入错误会回滚。

用户数据位于 `%APPDATA%/CameraFrameworkEditor`。`settings.json` 保存最近目录及布局；`recovery/<时间戳-随机标识>/manifest.json` 记录修改前文件及原路径。通过“文件 / 查看恢复副本”定位，恢复副本目前手动还原。

## 运行宿主与回归接口

正常界面的操作见上方“可玩的相机试验场”。每次运行先校验当前草稿并创建独立 Lua 会话，启动时采用闲置装置，随后由能力事件驱动装置切换。模拟固定以 60 Hz 单步推进，每一步完成后发送输出，正常负载下输出目标为 60 Hz；不再每两步合并输出。调度按单调时钟计算期限，繁忙时不并发积压 Lua 命令，严重落后时重设期限；实际输出频率受执行耗时影响。鼠标增量按绘制帧合并发送，按键边界先提交待处理鼠标输入，失焦／暂停时清空。渲染直接使用真实 Lua 输出，不额外叠加相机平滑。

`Simulation.start(..., {mode:'game', ...})` 提供可玩宿主。未指定 `mode` 的历史自动演示接口仍供测试使用，覆盖单装置进入、两秒保持、退出、业务 Id 选择与旧速度参数；正常界面不调用该演示流程。输入命令仅交给可玩宿主，失焦和暂停会清除按键与待处理输入。

三个通道快照来自框架本身。Three.js 根据最终位置、朝向、FOV、宽高比及正交参数呈现画面；地图材质透明度使用真实遮挡处理结果。宿主适配不等价于完整 UE 世界，未支持的能力及引擎效果仍需 UE 验证。

当前基本效果文件协议为 10、后处理协议为 2。基本 `.effect` 仅保存十二个相机通道，不再挂载后处理资产。独立资产位于 `Assets/PostProcessingAssets/`，现有四份模板为 `OwnerVelocity/{MovementSpeed,VelocityX,VelocityY,VelocityZ}.postProcessing`，均为空输出、Manual 绑定，不自动改变画面。

目录中点击 `.postProcessing` 打开专属窗口，同一资产重复打开时聚焦已有窗口。窗口保持左侧分组目录、右侧详情的 4:6 布局，分隔线支持拖动、键盘微调和比例记忆。属性卡使用独立 `PostProcessing/InterfaceRegistry.lua` 中的 Provider 对象与接口；基本效果仍使用自己的注册表。后处理资产拥有自己的 Source、Domain、Mode 和 Priority，布尔来源的定义域只读为 `{0} or {1}`。

Mode 保持 Lua 枚举原名 Target / Add。Target 按通道择优，Priority 越大越优先；同级有效目标冲突由 Lua 报错。Add 对通道增量求和。表格列为“通道 / 目标值域或增量值域 / 映射曲线 / 是否写入”。269 个数值通道及分组取自实际 Lua 字段目录，分组与通道支持双语、专属图标和搜索；Lua 标识、接口、路径、参数与枚举不翻译。未写入行仅为窗口预设，不参与编译或仲裁。Target 缺省预设为字段原生默认值，Add 为零；非恒定值域需配置曲线。

“绑定与平滑”页编辑当前资产在 `PostProcessing/Bindings.lua` 中的全局绑定：Id、Always / Manual / Space / Rig / Switch 激活方式，以及需要的空间名和装置名。空间与装置名使用运行时注册名称。新增绑定默认为 Manual，须由业务调用 `runtime.PostProcessing:SetActive` 激活；Always 自动持续参与，其他方式由实际管理器状态决定。共享基准值与响应时间常数按输出通道配置，影响所有绑定。时间常数为秒，零表示不平滑。

绑定和资产共用文档草稿。后处理窗口“保存”将当前资产与绑定草稿一同校验、写入；在绑定页撤销／重做作用于绑定文件。字面量 Lua 配置可表格编辑，含动态 Lua 代码的绑定只提供源码入口，不尝试改写执行代码。

全框架唯一产物为 `Assets/PostProcessingAssets/Framework.postProcessingPlan`。保存资产或 Lua 源码、创建／复制／移动／删除资产时，调用所选工作区真正的 `PostProcessing.Compiler`。源配置和产物一起备份、提交，写入失败回滚；校验期间发生外部修改则拒绝覆盖。重命名后处理资产或其文件夹会同步字面量绑定路径；有绑定引用的资产不允许删除。生成计划允许查看摘要或只读源码，禁止编辑、复制、移动和删除，包含该文件的目录同样受保护。

游戏启动用当前全部草稿编译内存计划，不改写磁盘；相机和后处理均由工作区 Lua 执行。后处理运行独立于相机装置管线，预览只读取最终输出，不在 JavaScript 再次计算优先级、增量或平滑。注册表、曲线和字段目录改变同样进入编译校验。
